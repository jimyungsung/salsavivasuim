# Review — October 2026

A pass over the daily concept as it stood on 5 October 2026 (`main` at
`15fba10`): the live site walked on a phone as a visitor, the member and admin
code read end to end, and the worst claims checked by hand. Work through it top
to bottom; tick items off here as they land, with the PR that did it.

**The state of things.** Nothing is live: 3 menus and 12 routines are drafts,
the 3 exercises are drafts, one routine holds one exercise, and the only
account is the admin's. A visitor who signs up today gets an empty Today.

## 1. Bugs a first member would hit

Done on branch `first-member-fixes`: `lib/clock.ts` (the member's time zone,
from a cookie the browser sets) for today, the greeting and "done this week";
copy-then-swap in `useMenu`/`resetDay`, keeping only playable exercises; a
weekday swap plus the unique index `routines_one_per_weekday` (applied).

- [x] **"Use this menu" can wipe the week.** `useMenu` deletes every drill, then
  copies the menu day by day; `copyRoutine` inserts a day's items in one go,
  and "own drill items" requires `can_access(video_id)` while "routine items
  follow their routine" does not check the exercise. One draft or encoding
  exercise fails the insert after the week is gone, with a raw RLS error.
  `resetDay` has the same shape. Copy only what the member can play, and copy
  before deleting.
- [x] **Done never resets.** `drill_slots.done_at` is read with no week scope
  (`lib/week.ts`), so a Monday ticked once is ticked every Monday after.
- [x] **Today is the server's day, in UTC.** `todayWeekday()` runs on Vercel,
  so before 09:00 in Korea `/today` shows yesterday. The greeting is computed
  from the hour on both server and client, so it can disagree with itself.
- [x] **Two routines on one weekday lose one.** `setRoutineWeekday` checks
  nothing and there is no unique index; members get whichever copies last.
- [x] **Apple sign-in is a dead button.** Only Google and email are enabled in
  Supabase.
- [x] **`published_at` is overwritten** on every open of a menu, against its own
  comment.

## 3. Get one week live (the back office)

Today: about 35 page visits and 250 inputs to turn 12 clips into a live week.

Done on branch `publish-week`: `publishWeek()` with the readiness list in
`app/admin/readiness.ts` (every way of opening a menu goes through it); draft /
open for routines and exercises, "soon" only on menus as a card with no
button; "+ New week" with a day pattern, and everything created opens at once;
bulk edit, "No tags" and "Draft" filters, and polling in the media library;
honest preview labels; a members-on-this-week count; a warning before
unpublishing an exercise live days use; the loop checked against the stored
row. Still open: the picker's serial taps, the beat grid by ear, and the
"New week" builder as one page of day columns.

- [x] **One "Publish week".** Four states must line up by hand: exercise
  `publish`, footage `status`, routine `status`, menu `status`. The menu's
  Publish panel checks nothing; the overview's dropdowns skip every check; the
  routine's readiness list is advisory. One action on the menu: list the
  blockers for the whole week, then open the menu, its routines and their
  exercises that have footage.
- [x] **"Soon" means open for menus and routines, draft for exercises.** RLS
  shows anything not draft, and a "soon" menu offers "Use this menu". Keep
  draft/open; "soon" only on menus, as a card with no button.
- [x] **Bulk edit in the media library**: select many, set tags, difficulty,
  mirror, open; filters for untagged and draft; poll uploads still encoding
  (they read "Encoding…" until a reload).
- [x] **"New week" in one step**: a title and a day pattern make the menu and
  its routines, named by weekday; then a week builder (day columns, library
  beside) instead of six routine pages. `createMenu`/`createRoutine` return no
  id, so nothing opens after creating; every routine is "Routine 01".
- [ ] **Picker taps are serial** and lock the grid; no "already in" badge.
- [ ] **Beat grid by ear**: the player on the exercise page with tap tempo,
  "first beat here", "loop these 8 counts". Today it is raw milliseconds, and
  saving one field disables the next.
- [x] **Quick drills** take five steps each and trip a "no weekday" warning.
- [x] **Previews show the admin view** (drafts included). Label them, or build a
  "what members get" panel from the same rules as Publish week.
- [x] Edits to a live menu never reach members who already copied it; say so
  next to Publish, with a count.
- [x] Unpublishing an exercise used by open routines gives no warning.
- [x] The loop check in `setVideoFields` never runs (one field per save), so the
  raw constraint message reaches the banner.
